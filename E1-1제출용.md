포트 연결이 왜 필요할까요?
포트 매핑이 필요한 이유: 컨테이너는 문이 잠긴 격리된 방이에요. 방 안에서 웹 서버가 돌고 있어도, 밖(내 브라우저)에서는 들어갈 수가 없어요. 그래서 내 컴퓨터의 문(포트) 하나를 컨테이너 안의 문과 이어주는 것이 포트 연결이에요.
- 컨테이너는 격리된 환경이라 밖에서 바로 접속할 수 없다.
- -p 8080:80 으로 내 컴퓨터의 8080번 포트와 컨테이너의 80번 포트를 연결해야 브라우저로 접속할 수 있다.

💡 컴퓨터에는 번호가 붙은 출입구(포트)가 많이 있어요. nginx는 컨테이너 안에서 80번 출입구를 써요.

[바인드 마운트 vs 볼륨]
- 바인드 마운트: 내가 정한 호스트 폴더를 직접 연결, 파일을 고치면 바로 반영 (개발할 때 편함)
- 볼륨: Docker가 관리하는 저장소, 컨테이너를 지워도 데이터 유지 (데이터 보관용)

💡 Git은 내 컴퓨터 안에서 파일의 변경 기록을 남기는 도구예요. 게임의 "세이브 포인트"처럼 언제든 이전 상태로 돌아갈 수 있어요. GitHub는 그 기록을 인터넷에 올려서 보관하고 다른 사람과 공유하는 사이트예요. 이게 미션의 “Git과 GitHub의 역할 차이”의 답이에요. 메모해 두세요!

Git = 로컬(내 컴퓨터) 버전 관리 도구
GitHub = 원격(인터넷) 협업 플랫폼

[트러블슈팅 - VSCode가 WSL에 연결되지 않음]
- 문제: code . 로 VSCode를 열었는데 터미널이 우분투가 아니라 PowerShell(\\wsl.localhost\Ubuntu\... 경로)로 열림
- 원인 가설: VSCode에 WSL 확장 프로그램이 없어서 우분투 안이 아니라 윈도우에서 폴더를 열었다
- 확인: 터미널 프롬프트가 PS ...> 로 나오고, 왼쪽 아래에 WSL: Ubuntu 표시가 없음
- 해결: VSCode에 Microsoft의 WSL 확장 프로그램을 설치하고, VSCode를 닫은 뒤 우분투에서 다시 code . 로 열었다
- 결과: 왼쪽 아래에 WSL: Ubuntu가 표시되고, 터미널 프롬프트가 wymm01@...:~/my-web$ 로 바뀜
